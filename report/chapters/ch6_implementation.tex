\section{The Wire Protocol}
\label{sec:wire_protocol}

A single WebSocket per session carries two channels: JSON text frames for control,
and tagged binary frames for media. Every binary frame is prefixed with a one-byte
type tag (Table~\ref{tab:bintags}); every JSON message carries a \texttt{type}
field (Table~\ref{tab:jsonmsgs}). The contract was frozen early in development and
is documented in \texttt{docs/protocol.md}; anything out of protocol is logged and
ignored, optionally answered with a \texttt{protocol\_violation} error, so an
old client can never crash the server.

\section{Backend Organization}
\label{sec:backend_org}

The backend is a single Python process organized in four layers.

\textbf{API layer} (\texttt{api/}). The WebSocket router dispatches incoming
messages: JSON text frames by their \texttt{type} field, binary frames by their
one-byte tag. The frame handler decodes JPEG payloads to RGB arrays via Pillow and
stores the latest frame (with its timestamp) on the session --- task loops always
read the freshest frame rather than queuing frames, so processing can never fall
progressively behind the camera. The audio handler runs the complete push-to-talk
pipeline described in Section~\ref{sec:voice_pipeline}. The \texttt{Session}
object owns all per-connection state: the FSM, the latest decoded frame and its
timestamp, the latest motion state and compass heading, the task context (target
or destination, start time), the last spoken phrase (for the ``repeat'' command),
and the handle to the running task loop's asyncio task; an \texttt{asyncio.Lock}
serializes concurrent sends over the socket, since the WebSocket object is not
safe under overlapping \texttt{send} calls.

\textbf{FSM layer} (\texttt{fsm/}). The five-state task machine of
Section~\ref{sec:fsm}, implemented as an explicit transition function with
subscriber callbacks; Table~\ref{tab:fsm_transitions} lists the complete
transition table as implemented --- every pair not shown is rejected with a
logged warning and no state change. The session subscribes: on every transition it
runs exit hooks for the old state (cancelling the old task loop), entry hooks for
the new state (starting the new task loop, reading the target from the task
context), and pushes the new wire-format state name to the client. Entering the
transitional ReturningToIdle state schedules \texttt{cleanup\_done} for the next
event-loop tick, so the client observes both transitions in order.

The distinction between \texttt{task\_abort} and \texttt{user\_stop} is a
deliberate accessibility decision: a voice ``cancel'' during a task drops back to
\emph{listening}, so the user can immediately speak the next command; only the
explicit Stop gesture (or a fatal condition) returns the session to Idle, where
the next interaction requires the Start button --- which a blind user would have
to hunt for mid-flow.

\textbf{Services layer} (\texttt{services/}). Speech recognition, command parsing,
TTS, object detection, hand pose, spatial reasoning, and guidance phrase
generation, each a stateless, individually importable module. Heavy ML imports are
deferred to first use behind thread-safe, double-checked lazy loaders, so
importing a service --- in tests, or at server start --- costs nothing; the pure
helpers inside them (detection parsing, landmark conversion) are directly
unit-testable without any ML framework installed. The spatial-reasoning module
carries the complete per-class size-prior table (Table~\ref{tab:priors}): for
each supported COCO class, the apparent size --- the larger of the box's width and
height as a fraction of the frame --- expected when the object sits at arm's reach
(${\sim}40$\,cm) in front of a typical phone camera.

\textbf{Task engines.} Object Allocation (which contains the reach-guidance phase)
and the Navigation package, each an asynchronous per-session loop created by the
FSM entry hook and cancelled by the exit hook --- so a task can never outlive its
state. Both entry hooks first cancel any loop already attached to the session, so
even a pathological double transition cannot leak a running loop.

\section{The Voice Pipeline}
\label{sec:voice_pipeline}

A push-to-talk release delivers one WebM/Opus blob to the audio handler, which
first saves it to disk (\texttt{captured\_audio/}, timestamped per session) for
offline inspection, then runs:

\begin{enumerate}[nosep]
  \item \textbf{Decode.} PyAV auto-detects the container from the bytes and
        resamples to the 16\,kHz mono float PCM Whisper expects; a resampler
        flush recovers the trailing samples, and a blob without an audio stream
        degrades to an empty transcription rather than an exception.
  \item \textbf{Transcribe.} faster-whisper (\texttt{base}, \texttt{int8}
        quantization, beam size 5, English, no VAD --- the push-to-talk gesture
        already trims the utterance) materializes the segments; a confidence proxy
        in $[0,1]$ is derived as $e^{\overline{\log p}}$ from the average
        log-probability. The transcription and confidence are pushed to the client
        for visual audit.
  \item \textbf{Parse.} The command parser classifies the utterance as a task
        command, a completion (confirm / cancel), an information query (describe /
        repeat), or unknown.
  \item \textbf{Act.} Task commands populate the task context \emph{before}
        firing \texttt{command\_recognized} --- the FSM entry hook reads the
        target synchronously inside the event. Completions route by context:
        ``got it'' during a task fires \texttt{task\_complete}; ``cancel'' during
        a task fires \texttt{task\_abort}, dropping back to listening; ``cancel''
        while merely listening ends the session.
  \item \textbf{Confirm.} Every path ends in a spoken response --- a confirmation
        (``Looking for your cup.''), a completion phrase naming the object, or a
        retry prompt --- synthesized by gTTS and shipped as an MP3 binary frame.
\end{enumerate}

Failures speak too: an undecodable or silent recording produces ``I didn't hear
anything. Please try again,'' alongside a machine-readable error --- the spoken cue
matters most, since a blind user has nothing to look at.

\subsection{The Command Parser}
\label{sec:command_parsing_impl}

Rather than matching whole utterances, the parser tries every (prefix, target)
split of the normalized input, fuzzy-matching the prefix against the command
templates and the target against the noun vocabulary with rapidfuzz's ratio
scorer, and taking the best-scoring combination over all splits; both endpoints
slide, so trailing filler (``\ldots{} please'') is tolerated. Normalization
lowercases, strips punctuation, collapses whitespace, and applies a synonym table
at word boundaries \emph{before} matching, canonicalizing common aliases and
mishearings (``fone'' $\to$ cell phone, ``fridge'' $\to$ refrigerator, ``sofa''
$\to$ couch, ``washroom'' $\to$ bathroom) so the fuzzy thresholds do not have to
be widened to absorb them. Completion and information phrases are matched with
token-set similarity --- so ``okay, I got it, thanks'' still matches ``got it''
--- but are restricted to short utterances and high score thresholds so they can
never steal a genuine find/navigate command. Table~\ref{tab:parser} lists the
vocabulary sizes and thresholds as committed.

The thresholds are deliberately permissive at the task layer: the worst case of a
false positive there is a wrong spoken confirmation the user immediately corrects,
whereas a false \emph{negative} forces a blind user to repeat themselves.
Completion matching is the opposite --- strict and length-limited --- because a
completion misfire silently ends a running task. During navigation, the same
mid-task channel additionally accepts direction hints --- \emph{left},
\emph{right}, \emph{ahead}, \emph{behind}, and their common variants --- consumed
by the multi-door dialogue of Section~\ref{sec:multi_door} when a scan has found
more than one door.

\section{The Object Allocation Engine}
\label{sec:oa_engine}

The engine separates decision from I/O. All policy --- the temporal filter, the
per-class buckets, the debounce, the throttles, the scan/lost/timeout edges, and
the reach state machine --- lives in a \texttt{GuidanceTracker} class that is pure:
it receives detections, the frame shape, an injected timestamp, the optional hand
pose, and the motion state, and returns an action and a phrase (or nothing). The
asynchronous shell around it only does I/O: it grabs the latest frame, runs YOLO
(and, when the tracker says the target is near, MediaPipe) in worker threads so
the event loop keeps serving the WebSocket, ships any pending haptic pulse
\emph{before} the phrase --- a brief vibration a beat before the voice cue is a
better ``you're close'' signal than after --- speaks the phrase, and sleeps to the
5\,Hz cadence. Two actions end the loop from inside: \emph{touch} fires
\texttt{task\_complete} (the auto-grasp exit), and \emph{timeout} fires
\texttt{user\_stop} after the apology. Table~\ref{tab:oa_constants} collects the
engine's tuning constants.

\section{The Navigation Engine: From Prototype to Integration}
\label{sec:nav_engine}

The navigation subsystem has an unusual history that shaped its implementation:
it was built and field-tested as a \emph{standalone prototype} before being
integrated into the backend.

\subsection{The Standalone Prototype}

The exploration pipeline was developed in a self-contained web demo: a minimal
FastAPI server exposing an HTTP \texttt{/detect} endpoint, a single-page frontend
that captured the rear camera and compass, POSTed one frame at a time (${\sim}3$
per second) as a base64 data URL, and spoke the returned guidance through the
browser's own speech synthesis. All state was module-global --- one user, one
journey. This shape was deliberate: it let the perception stack be iterated
against real phone footage in real rooms, failure by failure, with per-candidate
debug traces printed at the terminal for every keep/reject decision, without
touching the main backend. The prototype survives in the repository history
(branch \texttt{nav-integration}, directory \texttt{webdemo/}) as a record of
that phase.

\subsection{Integration}

Once field-tested, the prototype was ported into the backend's
\texttt{services/navigation/} package. The decision logic was kept unchanged
where possible, byte for byte; what changed is the plumbing:

\begin{itemize}[nosep]
  \item \textbf{Per-session state.} The module-global state dictionary became a
        \texttt{NavState} class, one instance per session, preserving dict-style
        access (\texttt{st["mode"]}) so the ported decision code reads identically
        to the field-tested original. Phase transitions go through
        \texttt{enter\_*} methods --- the only sanctioned way to switch phase ---
        each of which resets exactly the fields that phase depends on (fresh
        approach $\Rightarrow$ fresh obstacle debounce, fresh transit latch, fresh
        one-shot call-out flag).
  \item \textbf{Frame transport.} One HTTP POST per frame became a server-driven
        loop over the session's WebSocket frame stream: the engine reads the
        latest decoded frame each tick instead of being pushed one. One conversion
        happens at the boundary: the frame handler stores RGB, while the ported
        perception stack --- and every threshold tuned against it --- speaks
        OpenCV's BGR, so the engine converts once per tick.
  \item \textbf{Speech.} Browser speech synthesis became server-side gTTS over
        the same binary TTS channel every other task uses; the prototype
        frontend's queueing rules were re-implemented server-side as the
        priority/ambient policy of Section~\ref{sec:speech_discipline}.
  \item \textbf{Model loading.} The prototype loaded all models at import. The
        integrated package loads lazily behind a thread-safe
        \texttt{ensure\_loaded()}, called in a worker thread by the first
        navigation task in the server's lifetime --- announced to the user as
        ``Give me a moment while I get ready'' --- then reused by every later
        session; the models are stateless and shared, the state is not. A warm-up
        inference on a blank frame at load time moves GPU kernel initialization
        off the first real frame, which would otherwise be a long silence at the
        start of the first journey.
\end{itemize}

\section{Session Continuity and Haptics}
\label{sec:continuity}

Two smaller mechanisms round out the session model. \textbf{Resume.} On every
connection the server sends the client its session id (\texttt{session\_hello});
the client stores it in local storage. If the connection later drops with a task
active, the session's cleanup saves the task type and target into a resume pool
with a five-minute TTL (pruned on access, so the pool stays bounded). On the next
connect the client presents the old id; if live state exists, the server announces
``Resuming search for your cup,'' then re-drives the FSM through the normal
start-and-recognize path so the task loop restarts identically to a fresh request.
\textbf{Haptics.} The server sends symbolic pattern names that the client maps to
vibration sequences (Table~\ref{tab:haptics}); iOS has no vibration API, so the
client degrades silently there and voice remains the primary channel. Unknown
pattern names are ignored, keeping the vocabulary extensible without client
updates.

\section{Frontend}

Design decisions that matter:

\begin{itemize}[nosep]
  \item \textbf{Tap-anywhere push-to-talk.} Any pointer-down anywhere on the page
        (excluding the Start/Stop controls) starts recording and the matching
        pointer-up stops it, attached at document level so a drag off the
        original target still ends cleanly, with a blur handler as a safety net
        so a backgrounded tab never leaves the microphone hot. The visible PTT
        button remains as a large tactile target and recording indicator, but a
        blind user never has to hunt for it.
  \item \textbf{iOS audio unlock.} iOS enforces audio policy at two independent
        layers, and TTS clips arrive well outside any user gesture. The queue
        therefore primes \emph{both} inside the Start tap: it resumes a Web Audio
        context and plays a programmatically constructed silent WAV through one
        persistent \texttt{<audio>} element --- which is then reused, by swapping
        its source, for every subsequent MP3 clip. A fresh audio element per clip
        is silently rejected on iPhone; the persistent primed element is what
        makes the voice channel work at all on iOS Safari and Chrome.
  \item \textbf{Sequential playback.} Clips are queued and played one at a time
        through that element; nothing ever overlaps on the client side.
  \item \textbf{Sensor permissions inside the gesture.} iOS 13+ requires motion
        and orientation permission requests from inside a user gesture, so both
        monitors start from the Start button's click handler; either failing is
        non-fatal (the server falls back to plain debouncing and the compass-less
        scan respectively). Motion is classified from a one-second window of
        accelerometer deviation into still / moving / walking and sent only on
        state change.
  \item \textbf{No stale code.} The backend serves the frontend with
        no-cache headers, because mobile Safari's aggressive JS caching silently
        reintroduced already-fixed bugs during development.
  \item \textbf{Local speech fallback.} Browser speech synthesis is used only
        where the server cannot speak --- camera permission failures before the
        socket opens, and unexpected disconnections mid-session.
\end{itemize}

\section{Deployment}
\label{sec:deployment}

The backend serves the frontend same-origin, so a single HTTPS endpoint exposes
the whole system, and the page derives its WebSocket URL from its own origin ---
the same code works on localhost, behind a tunnel, or on a cloud host. For
development and demos, a Cloudflare quick tunnel provides a real HTTPS URL in one
command --- necessary because browsers permit camera and microphone access only
over HTTPS (or localhost):

\begin{lstlisting}
cd backend && uvicorn main:app --port 8000
cloudflared tunnel --url http://localhost:8000
\end{lstlisting}

The phone opens the printed URL; no certificates, DNS, or router configuration
are involved. Table~\ref{tab:models} inventories every model the system uses,
its size, its provenance, and when it loads. Public weights are fetched and
cached automatically on first use; the two custom door models are committed to
the repository, so a fresh clone reaches the complete working system with the
two commands above and no manual asset steps.

\section{Test Infrastructure}
\label{sec:test_infrastructure}

All decision logic is written as pure, injectable code: trackers and controllers
receive detections, frame shapes, timestamps, and sensor readings as arguments and
return actions and phrases --- no I/O, no models, no global clock. This is what
makes the automated suite possible: \textbf{281 collected test cases} across 13
modules (Table~\ref{tab:tests}), covering FSM transitions (valid, invalid, and
no-op, with subscriber semantics); command parsing across 50+ realistic
transcriptions including mishearings, synonyms, filler, and the completion,
cancel, and information vocabularies; spatial bucketing with per-class priors and
boundary cases; guidance phrase rendering; the reach-guidance state machine
including the dominant-axis rule and degenerate inputs; hand-landmark conversion;
YOLO detection parsing; the Object Allocation tracker end-to-end with scripted
frames and a fake clock (temporal filtering, debounce, throttles,
scan/lost/timeout edges, reach entry and the once-only touch exit); the
navigation goal model and arrival rules; the compass and bearing mathematics
including clustering across the $\pm180^\circ$ seam; and complete scripted
navigation journeys --- a full 36-heading compass scan, door selection from
clustered bearings, the guided turn, the call-out and path-clear verdict, the
at-door instruction, doorway transit gated on camera motion, the new room's scan,
directed indicator confirmation, and the arrival line naming the observed
evidence --- with the exact mode transitions and key phrases asserted at every
step. Session-isolation tests verify that concurrent \texttt{NavState} instances
share nothing.
